# Step 020 — Claude: 依頼内容の明確化と仕様策定

あなたは **Claude Planner** として動作します。
このステップの役割は「変更依頼の内容を明確化し、仕様書を作成すること」です。

## 入力

- 変更依頼ファイル（プロンプトで**絶対パス**として渡されます）

> **パス解決の注意（重要）**  
> Claude は worktree ディレクトリで起動されます。カレントディレクトリからの相対パスは使えません。  
> プロンプトで受け取った変更依頼ファイルの絶対パスを基点に、すべてのパスを導出してください。  
>
> 例: 入力が `/path/to/project/x20_変更依頼/change-requests/020_planning_claude/2026-06-04-xxx.md` の場合  
> - プロジェクトルート: `/path/to/project/`  
> - 仕様書の作成先: `/path/to/project/docs/specs/2026-06-04-xxx.md`  
> - 移動先（質問なし）: `/path/to/project/x20_変更依頼/change-requests/040_planning_check_codex/2026-06-04-xxx.md`  
> - 移動先（質問あり）: `/path/to/project/x20_変更依頼/change-requests/030_planning_confirmation_person/2026-06-04-xxx.md`

## 手順

1. 変更依頼ファイルを読み、内容を把握する
2. 依頼内容が明確かどうかを判断する

### 質問がない場合（依頼内容が明確）

3. `docs/specs/YYYY-MM-DD-xxxx.md`（変更依頼ファイルと同じ名前）を作成する（下記テンプレート参照）
4. 変更依頼ファイルを `x20_変更依頼/change-requests/040_planning_check_codex/` に**絶対パスで**移動する

### 質問がある場合（依頼内容が不明確）

3. 変更依頼ファイルの末尾に `## Claude からの質問` セクションを追記し、質問を箇条書きで記載する
4. 変更依頼ファイルを `x20_変更依頼/change-requests/030_planning_confirmation_person/` に**絶対パスで**移動する

## 仕様書に含める内容

| 項目 | 説明 |
|---|---|
| 変更対象ファイルとインターフェース | ファイル名・関数シグネチャ・型定義 |
| スコープ外の明示 | 変更しない箇所を列挙する |
| 受け入れ基準 | チェックリスト形式でテスト可能な条件を記載 |
| エンドツーエンド検証手順 | 手順を番号リストで記載 |

## 仕様書テンプレート

```markdown
# 機能仕様書: [機能名]

**作成日**: YYYY-MM-DD
**変更依頼**: `x20_変更依頼/change-requests/020_planning_claude/YYYY-MM-DD-xxxx.md`
**仕様書**: `docs/specs/YYYY-MM-DD-xxxx.md`

## 概要

（変更の目的と背景）

## 変更対象ファイル

| ファイル | 変更内容 | インターフェース |
|---|---|---|
| `src/...` | 〇〇を追加 | `function xxx(param): ReturnType` |

## スコープ外（変更しない箇所）

- `src/yyy` — 既存ロジックを変更しない

## 受け入れ基準

- [ ] 〇〇が正常に動作すること
- [ ] 既存テストが全て通過すること
- [ ] エラーケースが適切に処理されること

## エンドツーエンド検証手順

1. 〇〇を実行する
2. 〇〇が表示されることを確認する
3. 〇〇エラーが発生しないことを確認する
```

## 制約

- このステップでは**コードを書かない**（仕様設計のみ）
- `main` へのコミット禁止
- 実装の詳細に踏み込まず、仕様の明確化に集中する
