# Step 060 — 人間: インフラ事前作業

このステップは**人間（オペレーター）が対応**します。
AI が実装したコードをテストする前に必要なインフラ準備・環境設定を行います。

## 入力

- `change-request.md` の `## 機能仕様書` セクション（特に「オペレーター事前作業」または「エンドツーエンド検証手順」）

## 対応手順

1. 仕様書に「オペレーター事前作業」セクションがある場合はその内容を確認する
2. 以下の作業が必要かどうかを確認し、必要なものを実施する

| 作業 | 確認・実施内容 |
|---|---|
| Pipeline 展開・実行 | テーブル作成・変更用 Pipeline をインポートし、接続設定を確認して実行する |
| DDL 実行 | ビュー・関数・プロシージャ等、仕様書で明示された DDL のみ実行する。テーブル `CREATE TABLE` は手動実行しない |
| 環境変数・認証情報 | `.env` または設定ファイルを実行環境に配置する |
| 接続設定 | DB 接続文字列・API エンドポイント・Service Principal 等を設定する |
| パッケージインストール | `requirements.txt` 等に追加されたパッケージをインストールする |
| ファイル・フォルダ配置 | 実行環境に必要なファイル・フォルダを配置する |

3. 上記に該当する作業がない場合はそのまま次のステップへ進む

### 完了 → `070_testing_ai/` へ移動

```
変更前: 060_infra_person/2026-06-04-xxx/
変更後: 070_testing_ai/2026-06-04-xxx/
```

## 備考

- このステップでコードを変更しない（コード変更が必要と気づいた場合は `020_planning_ai/` へ戻す）
- Fabric の SQL analytics endpoint ではテーブル作成 DDL を実行しない。テーブル作成・変更は Pipeline 経由で行う
- `.env` 等の認証情報ファイルは git にコミットしない
- 作業内容を記録したい場合は `change-request.md` の末尾に `## オペレーター作業メモ` セクションを追記してよい（任意）
