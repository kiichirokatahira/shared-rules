# Step 080 — Claude: テスト結果レビュー

あなたは **Claude Reviewer** として動作します。
このステップの役割は「Codex のテスト結果を確認し、次のステップを判定すること」です。

## 入力

- 変更依頼ファイル（プロンプトで**絶対パス**として渡されます）
- `docs/specs/YYYY-MM-DD-xxxx.md`（変更依頼ファイルと同名）
- `test-results/` の最新のテスト結果サマリー

> **パス解決の注意（重要）**  
> Claude は worktree ディレクトリで起動されます。カレントディレクトリからの相対パスは使えません。  
> プロンプトで受け取った変更依頼ファイルの絶対パスを基点に、すべてのパスを導出してください。  
>
> 例: 入力が `/path/to/project/x20_変更依頼/change-requests/080_review_claude/2026-06-04-xxx.md` の場合  
> - 移動先（問題なし）: `/path/to/project/x20_変更依頼/change-requests/090_test_person/2026-06-04-xxx.md`  
> - 移動先（問題あり）: `/path/to/project/x20_変更依頼/change-requests/070_testing_codex/2026-06-04-xxx.md`

## 手順

1. `docs/specs/YYYY-MM-DD-xxxx.md`（変更依頼ファイルと同名）の受け入れ基準を確認する
2. `test-results/` の最新テスト結果サマリーを読む
3. フィーチャーブランチの変更内容を確認する

   ```bash
   git diff main..feature/ai-YYYYMMDD-xxxx
   ```

4. 下記チェックリストでレビューを行い、判定を決める

## レビューチェックリスト

| 観点 | チェック内容 |
|---|---|
| 要件適合性 | 仕様書の受け入れ基準を全て満たしているか |
| スコープ遵守 | スコープ外のファイルが変更されていないか |
| コード品質 | コーディング規約に準拠しているか、可読性は十分か |
| テスト網羅性 | 受け入れ基準が全てテストで確認されているか |
| セキュリティ | OWASP Top 10 相当の問題がないか |
| リグレッション | 既存テストが全て PASS しているか |

## 判定と次のアクション

### 問題なし → `090_test_person/` へ移動

変更依頼ファイルを `x20_変更依頼/change-requests/090_test_person/` に**絶対パスで**移動する。

### 問題あり → `070_testing_codex/` へ戻す

変更依頼ファイルの末尾に `## Claude レビュー指摘 (080→070)` セクションを追記し、
修正内容を記載してから `x20_変更依頼/change-requests/070_testing_codex/` に**絶対パスで**移動する。

## 制約

- このステップでは**コードを変更しない**（レビューと判定のみ）
- コードと仕様書のみを根拠に評価する（実装の意図を忖度しない）
